# TUI First Screen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an `ephact tui` command with a ratatui splash screen showing the project emblem and a keyboard-driven home screen.

**Architecture:** Keep TUI code independent under `src/tui`. `app.rs` owns terminal lifecycle, screen state, rendering dispatch, and transitions; `event.rs` abstracts polling and key reads; `screen/splash.rs` and `screen/home.rs` only render their respective views. Add a lightweight Clap command that delegates to the TUI entry point while existing CLI commands remain unchanged.

**Tech Stack:** Rust 2024, Clap 4, ratatui 0.29, crossterm 0.29, ratatui `TestBackend` for render tests.

## Global Constraints

- The TUI is launched as `ephact tui`.
- The TUI lives in a top-level Rust module named `tui`.
- The TUI uses ratatui.
- The splash displays `assets/project_emblem.txt` and advances on any key.
- `q` exits from both splash and home screens.
- Terminal raw mode and alternate-screen state are restored on normal exit and errors.
- Workflow execution and menu actions are out of scope for this slice.
- Existing non-TUI commands retain their current behavior.

### Task 3: Add event handling, state transitions, and terminal lifecycle

- Modify: `src/tui/mod.rs`

**Interfaces:**
- `event::read_key() -> Result<KeyEvent, Box<dyn Error>>` polls and reads one key event.
- `app::Screen` has `Splash`, `Home`, and `Exit` variants.
- `app::App::handle_key(KeyEvent)` transitions Splash → Home on any key, and either active screen → Exit on `q`.
- `tui::run()` creates the terminal, runs the app, and restores terminal state before returning.

fn any_key_advances_splash_to_home() {

#[test]

    let mut app = App::new();
    app.handle_key(KeyEvent::new(KeyCode::Enter, KeyModifiers::NONE));
    app.handle_key(KeyEvent::new(KeyCode::Char('q'), KeyModifiers::NONE));
    assert_eq!(app.screen(), Screen::Exit);
}

- [ ] **Step 3: Implement the minimal state machine**

Implement `Screen` and `App` with private state and public `new`, `screen`, and `handle_key`. `handle_key` must check `q` first, then advance only from `Splash`; keys other than `q` on `Home` do nothing.

Implement `event::read_key` with `crossterm::event::poll(Duration::from_millis(100))` and `event::read`, returning only key events and continuing to poll until one arrives.

Implement `tui::run` with `ratatui::init()` and a guard pattern that calls `ratatui::restore()` before returning the app result. The loop draws the current screen and processes one key at a time until `Screen::Exit`. Do not sleep or use a fixed splash timeout.
